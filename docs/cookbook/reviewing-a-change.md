# 评审一次改动

目标：在合并前判断"它真的成立吗"，而不是"看起来没问题"。

1. **先看意图**：读提交信息与相关 `.agent/notes/`，确认这次改动落在六条不可违反的哪一条上
   （`AGENTS.md` 的表）——越界就要拦。
2. **看全量 diff**（不是只看摘要）：`git diff --stat` 之后逐文件看，重点三件事 ——
   ① 有没有把"失败"变成"静默"；② 有没有新增**第二处真相**（同一事实写两遍）；
   ③ 文档是否同步（改行为改 README/quickstart，改边界改 rules + AGENTS）。
3. **跑门禁并贴输出**：

   ```bash
   npm test          # Python 全量 + 组件库导入检查 + 文档站构建
   ```

4. **逐条找证据**：改动涉及的边界必须有测试锁着；新行为要有断言；文档里新增的路径/链接由
   `tests/test_docs.py` 真实校验。没有测试保护的行为变更 = 不算完成。
5. **盯住"配置类静默失效"**：`@source`、别名、`base`、路径、环境变量这类东西错了往往不报错，
   必须真跑一遍（构建产物里 grep、或浏览器里看计算样式）。踩过的例子：
   [Tailwind `@source`](../../.agent/notes/implemented/bug-fix/2026-10-07-tailwind-source-after-move.md)。
6. **通过标准**：全绿；每条结论后面都有命令与输出；未验证或已知取舍写在提交信息/笔记里，
   不写"应该没问题"。
