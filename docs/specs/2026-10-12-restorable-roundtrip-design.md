# 可还原脱敏（脱敏 → 交 AI → 还原）设计

- 日期：2026-10-12
- 状态：已实现（核心闭环）
- 状态码参考：`.agent/notes/` 的状态词

## 为什么要做

场景：用户先把文档脱敏，交给 AI 改写（改格式、换措辞、补结构），拿回来之后希望把脱敏掉的
信息填回去，**且文档格式与样式保持原样**。

改之前的机制没有考虑还原，而且**不是补一个 `restore` 就能补上的**。

## 关键判断：断点在脱敏那一步，不在还原那一步

现有策略里：

| 策略 | 产物 | 可逆？ |
|---|---|---|
| `mask` | `138****5678` | 否 —— 中间四位在替换时就没了 |
| `redact` | `**` | 否 —— 整体盖掉 |
| `remove` | 空串 | 否 —— 连位置都没有 |
| `placeholder` | `<PHONE_1>` | 是 —— 可寻址 |
| `pseudonym` | `林芳` | 是，但那是"看起来像真的"，不是可寻址锚点 |

`mask` / `redact` 在**写出去的那一步**就把原文丢了。这是数学上的不可逆，任何事后实现都变不回来。
所以「先脱敏 → 交 AI → 还原」这条链，第一环必须换成**可寻址的锚点**，而不是在最后一环想办法补救。

配套的第二件事：`restore` 原先只吃 txt/md/csv，理由是「docx/xlsx 是回写产物，没有可替换的纯文本」。
这个理由成立的前提是"整体读出→替换→写回"这种做法 —— 而那恰恰是会毁掉格式的做法。正确的做法是
**逐文字槽就地替换**（见下），前提一换，这条限制就不成立了。

## 三个设计决策

### 1. 锚点用 `{{TYPE_N}}`，不用 `<TYPE_N>`

单尖括号在 markdown / HTML / LaTeX 里都有语法含义：

- HTML 转义成 `&lt;PERSON_1&gt;`，正则匹配不上
- 模板引擎（`{{ }}` 恰好是 Jinja/Nunjucks 的写法）把 `<PERSON_1>` 当标签吞掉
- 经 AI 改写一道，锚点就再也认不出来了

双花括号是模板占位符的通用写法，各处都当普通文本，AI 也不会顺手改写它。

匹配时**故意宽松**：容忍锚点内部空白（`{{ PERSON_1 }}`）、大小写（`{{person_1}}`），
匹配前先做 HTML 反转义。这解决的是"同一个锚点被包了一层"，不该判成还原失败。

### 2. 定位靠锚点文本，绝不靠位置

最容易踩的坑：AI 会重排段落、合并单元格、改写句子，脱敏时记进 `manifest` 的
`locator.paragraph=7` 早就失效了。拿位置去定位会还原到错的地方 —— 而且是静默的错。

所以还原端做的是：**打开 AI 交回来的文件 → 全文扫锚点 → 就地替换**。位置信息只用于
"这个锚点本该属于哪个文件"的对账报告，不参与定位。

锚点方案天生对重排免疫，这正是它存在的理由。

### 3. 必须对账，漏了要说

按项目「召回优先 / 不静默」的纪律：

| 情况 | 处理 | 理由 |
|---|---|---|
| 锚点不在映射表里（AI 编的） | **原样保留，不替换**，列进 `unknown` | 猜一个原文填进去 = 把无关人名插进正文 |
| 映射表里有、成品里没出现（AI 删了） | 列进 `missing`，退出码 2 | 静默少还原比不还原更危险 |
| `remove` 策略（替换值为空串） | 不进反向表 | `str.replace("", 原文)` 会把原文插到每个字符之间 |

`missing` 的判定**必须按文件**，用 `manifest.json` 里该条目的 `anchors` 字段。
拿整张映射表对账会把别的文件的锚点误报成缺失。

## 实现要点

### 格式保持怎么做到的

**只改 `run.text` / `cell.value`，一个属性都不碰。** docx 的字体、字号、颜色、下划线挂在 run 的
`w:rPr` 上；xlsx 挂在 cell 上。只要不读成纯文本再重建，这些属性就原封不动。

实测：锚点被拆到 3 个 run 时仍能回填，起点 run 的粗体/14pt/`#c7000b`/SimSun 完整保留。

### 跨 run 切分

锚点被拆到多个 run 是常态（拼写检查、格式刷、格式往返转换都会拆）。逐 run 各自替换会一个都
匹配不上。

做法：先把整段文字拼出来找锚点 → 拿到**全段坐标系**里的 span → 把 span 映射回各 run 的区间改写。
这与 `writers._redact_paragraph` 是同一套偏移算法的逆运算（那边原文→锚点，这边锚点→原文）。

替换值落在**起点所在的那个 run** 上，后续被覆盖的 run 只清掉重叠部分 —— 它们的字体属于被替换掉的
那段文字，留着会串味。

### 无锚点时不动文件

一个锚点都没有时，直接 `write_bytes` 原样复制。让 python-docx 重写一遍会丢掉它不认识的部件
（批注、修订、内容控件的一部分），属于无谓的损伤。

### 一个真实的安全坑

`redact` 的替换值是 `**`，而 **markdown 的加粗也是 `**`**。拿它做字面全局替换，等于把整篇文档的
加粗标记换成某个当事人姓名。所以纯符号替换值必须排除在字面替换之外。

同理，docx/xlsx 路线**只认锚点**，不做字面替换 —— 打码值和假名不是可寻址的，在 docx 里可能跨 run，
按字面全局替换会打到不相干的地方。

## 明确做不到的

| 场景 | 结果 | 为什么 |
|---|---|---|
| PDF / 扫描件 / 图片 | 不还原，明确拒绝并指向 docx | 命中页整页栅格化，原文字层已被物理删除 |
| `mask`/`redact`/`remove` 的历史产物 | 不可还原 | 原理上不可逆 |
| 页眉/页脚/脚注/文本框里的锚点 | 找不到 | 抽取器本来就不抽这些 —— 前后一致，不新增缺口 |
| 文本变长导致换行变化 | 不可避免 | 但这是原文的真实长度 |
| AI 只回传 markdown | 字能还原、样式回不来 | 格式信息已在 AI 那一步丢失 |

## 被否决的备选

**把映射表内嵌进 docx 的自定义 XML part。** 好处是还原不需要外部文件、AI 也拿不到映射。

否决理由有二：AI 处理后原文件通常整个重建，内嵌数据会跟着丢；而内嵌原文会让「脱敏件」本身变成
高危文件，安全模型反而更差 —— 一个能被人随手打开的脱敏件，里面塞着完整身份证号。

映射表全程留在本地，靠流程纪律保证不外发。

## 落地范围

已实现（核心闭环）：

- `strategies.py`：`anchor` 策略；`irreversible_types()` 供 run 结束时报警
- `redaction/restorers.py`：按扩展名路由的还原器 + 容错匹配 + 对账结果
- `redaction/mapping.py`：`uses` 字段（替换值 → 次数）、`reverse_table()`
- `pipeline.py` / `job.py`：manifest 条目加 `anchors`（仅在真有锚点时写，向后兼容）
- `cli.py`：`restore` 从"只吃文本"扩成按格式路由；`--report` / `--expected`；默认产物名
  `【脱敏版】x.docx` → `【还原版】x.docx`（替换而非叠加）
- `roundtrip.yaml`（**已并入默认**，文件已删）：全类型 `anchor`，见下面「后续调整」
- `packages/docanon-core/tests/test_restore_roundtrip.py`：20 项，覆盖四类翻车方式

已实现（Web 入口，同日补）：

- `POST /api/restore`：入参 `{token, filename, content_b64, expected?}`
- `/api/anonymize` 出参加 `restorable` / `anchors` / `restore_token`；批次逐份带 `restorable` + `anchors`
- `apps/web/src/components/RestorePanel.tsx`：选文件 → 还原 → 下载产物与对账报告
- `roundtrip.yaml` 进 L1 下拉（排最后 —— 它是给特定链路用的，不是日常口径；**后已并入默认，见下**）
- `profiles.STRATEGY_VALUES` 放开 `anchor`：**前提是还原入口已存在**，否则用户会拿到一份
  脱敏后再也填不回来的产物，那比拒绝更糟
- L2 策略表给 `redact`/`mask`/`remove` 标「不可还原」
- `packages/docanon-core/tests/test_server_restore.py`：13 项，含路径穿越防护、PDF 拒绝、失败不留残留

Web 侧的两条设计要点：

1. **映射表不经浏览器** —— 它就是原文本身，只在服务端。还原凭服务端发过的 `token` 指回去，
   还原件落**独立的 `/restored/` 目录**，与可外发的脱敏件分开（同"zip 不含 mapping.json"的道理）。
2. **批次里一批共用一份 `mapping.json`** —— 还原的 `expected` 必须取**这一份的**锚点（整批还原时把
   这一批逐份的锚点都带上）。拿批次合计去对账，会把别的文件的锚点误报成缺失。

未实现（下一轮）：

- AI 只回传 markdown 时，以原件为模板做 3-way merge 兜底（文字能还原、样式回不来）
- 页眉/页脚/文本框的抽取（既有缺口，独立课题）

## 后续调整：可还原内建为默认（2026-10-12 晚）

原方案把"可还原"做成**一套要手动选的方案**（`roundtrip.yaml`），默认口径仍是 `mask`/`redact` ——
于是"办公文档能脱敏又能还原"这件事得靠用户自己知道去切方案。这与最初的设计（策略档位里就有"可还原"）
不符，改回默认：

- **三套内置方案（`default.yaml` / `onnx.yaml` / `llm.yaml`）全类型改 `anchor`**：方案只再决定**识别能力**
  （规则 / +小模型 / +大模型），不再决定能不能还原。`roundtrip.yaml` 随之删除（语义已内建）。
- 打码/盖掉（`mask`/`redact`/`remove`）降级为 **L2 逐类型策略**里的可选项，界面标「不可还原」。
- 新增整批还原：`POST /api/restore/batch`（入参 `{token, items, anchors?}`，**一份失败不拖垮整批**）
  + `GET /api/restore/{rtoken}/zip`（还原件整包）；`RestorePanel` 支持多选文件 / 选文件夹。
