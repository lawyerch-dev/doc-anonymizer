# 事故复盘 0001：搬家改了路径，Tailwind 类名被静默摇掉

## 执行摘要

`website/` 从 `apps/website/` 搬到仓库根目录后，`global.css` 里的 `@source "../../apps/ui/src"`
少了一层，指向不存在的目录。Tailwind 对不存在的 `@source` **不报错**，只是扫不到共享组件库里的类名，
于是 `sr-only`、`bg-brand-*`、`animate-aurora-*` 全被摇掉。表现成三个看着无关的 bug：数字组件
显示成双份（`4` → `44`）、aurora 背景全透明、渐变文字变纯色。**已发布的落地页上就是坏的**，
而我先按"组件写错了"排查了两轮才去看计算样式。

## 影响

- 落地页首屏的三处视觉/可用性问题是**线上可见**的（站点构建与截图都会照常成功）；
- 屏幕阅读器文本可见（`sr-only` 失效）属于可访问性回归；
- 花费：两轮错误方向的排查 + 一次浏览器实测。

## 时间线

1. 网站从 `apps/website/` 移到仓库根（同时改 `sync-content.py` 的仓库根深度、`dev.sh` 引用）；
2. 构建通过、页面渲染正常 → 我把站点当成"没问题"；
3. 集成 velora 全量组件后，浏览器截图里出现数字双份/光晕透明/渐变失效；
4. 排查：怀疑组件 props → 怀疑 CSS 变量 → 用 WebKit 读**计算样式**，发现 `sr-only` 根本没生效；
5. 定位 `@source` 路径少一层；修正为 `../../../apps/ui/src` 后三项一起恢复；
6. 补守卫 `test_tailwind_sources_resolve`（`@source` 必须指向真实存在的目录）。

## 根因

`@source` 是**构建期路径配置**，写错时 Tailwind 静默忽略（它不把"扫描目录不存在"当错误）。
配置类错误不报错，只在**运行时表现层**露头 —— 而表现层的症状分散在三个不相关的组件上，
让人本能地往"组件有问题"方向排查。

## 为什么没兜住

| 本该拦住它的网 | 为什么失效 |
|---|---|
| 站点构建 | 构建成功：少扫一个目录不影响构建结果 |
| 组件库的导入检查（`npm run check -w ui`） | 检查的是**导入路径规范化**，与 Tailwind 扫描无关 |
| 文档里的路径守卫 | 守卫只查 markdown 里的**文件路径**，不查 CSS 里的 `@source` |
| 截图检查 | 我看了截图却把它当成组件问题，没有把"整层样式不生效"当成线索 |
| 我自己的"真跑一遍"纪律 | 跑了**构建**，没跑**浏览器计算样式** —— 构建绿不等于样式生效 |

## 护栏

- `tests/test_docs.py::test_tailwind_sources_resolve`：每个 `@source` 必须指向真实存在的目录
  （现在 4 条 `@source` 全被查）。
- 站内链接同理：`test_website_internal_links_go_through_base`（手写 `href="/…"` 在子路径部署会 404）。
- 文档纪律升级：**配置类改动必须真跑一遍并看计算样式/产物**，写进
  [`docs/cookbook/reviewing-a-change.md`](../../docs/cookbook/reviewing-a-change.md) 第 5 条。

## 如果重来

看到"整层样式不生效"（而不是单个组件错位）时，第一步就该打开开发者工具读计算样式，
而不是猜组件 props —— 症状的**分布范围**本身就指向"扫描/加载"这一类原因。
