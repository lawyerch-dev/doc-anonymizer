# Agent Note: DOCX 回写偏移错位: 超链接里的字既漏脱敏又被改错

Status: implemented

## 问题

`paragraph.text`(抽取拿它算字符偏移)含超链接里的文字, 而 `paragraph.runs`(回写拿它定位 run)
只认段落的**直接子** `w:r`。两边各算一套偏移, 后果是双份的:

- **漏**: 超链接里的邮箱原样留在产物里 —— Word 里点得开的邮箱/网址默认就是这种写法;
- **损坏**: 替换值落到错误的字符上。实测 `B 行: 邮箱 a@b.com 联系电话 13800001111`
  变成 `B 行: 邮箱 a@b.coma***@b.com380000138****1111`;
- 而 manifest 记的是 `ok` + `EMAIL:1, PHONE:1` —— 静默, 这是最坏的形态。

同一类"文字在文档里、抽取看不见"的排布还有: 内容控件 `w:sdt`、嵌套表格(`doc.tables` 只认顶层)、
修订插入 `w:ins`、域代码 `w:fldSimple`; 连带的是: 可见文字改了, 但超链接目标(`mailto:`/URL)里
还留着原文, 这份文件里照样搜得到它。

为什么一直没被发现: `packages/*/tests` 里没有一个用例构造 docx(回写路径零断言),
而 `samples/` 是 `scripts/make_samples.py` 自己生成的 —— 检测器在拿自己出的题考自己。

## 决策

- 抽取与回写**共用一套遍历**: `packages/docanon-core/src/docanon_core/docx_walk.py`
  —— 段落顺序(含表格/嵌套表格/内容控件)与段落里的"文字槽"(含超链接/`w:ins`/`w:smartTag`/`w:fldSimple`)
  都由它给出, 两边不许各写一套;
- 本段被替换过的原文, 同时从 `w:instrText` 与超链接目标里抹掉(只抹换过的, 不做通用 URL 扫描);
- 段落定位失败**抛错**(变成 manifest 的 `error`), 不再像以前那样 `continue` 静默跳过;
- 页眉/页脚/脚注/文本框与文档属性仍不覆盖, 已在 README「已知限制」里写明。

## 证据

- `packages/docanon-core/tests/test_docx_output.py`: 8 条断言型用例, 其中 7 条在改动前的实现上是红的
  (唯一一条绿的是"纯正文跨 run 拆分", 那种排布本来就没问题);
- 实测三类排布: 超链接里是邮箱的、手机号在超链接之后的、只存在于超链接里的 —— 产物里搜不到原文, 前后文字完好。

## 教训

**同一份文本有两个视图, 就是错位的温床。** 凡是"算偏移的地方"与"写回去的地方", 必须指向同一个来源,
而不是两个都"看起来对"。第三方库里同名不同义的属性(`text` vs `runs`)尤其危险: 它不报错, 只给你错的结果。
